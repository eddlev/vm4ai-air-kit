# AIR Kit v0.6.0-preview.1

**Release channel:** Public Preview / Development

AIR Kit v0.6.0-preview.1 packages the repaired AIR Foundation `2.5.0` candidate for active use, field testing, integration experiments, and rapid feedback while AIR continues to evolve.

> **Versioning note:** `v0.6.0-preview.1` is the public AIR Kit release version. The bundled runtime components keep their own versions: Core/Control/Starter `2.5.0`, Governance/Handoff `2.3.0`, Specialist package line `2.4.0`, Runtime Route Map `1.0.0`, and Specialist Index `1.1.1`.

This release is **not labeled as a stable behavioral certification**. The full release-grade behavioral matrix is reserved for a later Stable milestone so fast-moving development is not blocked by repeatedly invalidated long-form manual test cycles.

## What changed

This preview closes three Foundation consistency defects identified after the prior Specialist-layer closure:

1. **Handoff Governance version drift** — strict Handoff state now aligns with Governance/Floor version `2.3.0`.
2. **Handoff restoration schema drift** — Core restoration semantics now use the schema-2.3 carriers `presentation_mode`, `presentation_mode_source`, and `evidence_capture_gaps`.
3. **Evidence-presentation semantic contradiction** — evidence sufficiency is now explicitly independent of whether presentation is standard or expanded.

The Runtime Route Map and downstream Specialist dependency closure were resealed against the repaired Foundation hashes. Specialist package versions remain `2.4.0`; the Specialist Index remains `1.1.1`.

## Release assets and provenance

The GitHub release workflow builds the public AIR Kit assets from the tagged repository source:

- `AIR-core.zip` — stable download name for the current AIR Kit core bundle
- `AIR-v0.6.0-preview.1-core.zip` — version-pinned copy of the same bundle bytes
- `AIR_CORE_MANIFEST.json` — packaged-file identities, component versions, source/release provenance, and assurance boundary
- `SHA256SUMS.txt` — SHA-256 checksums for the generated release assets

The exact release-asset hashes are generated by that workflow and should be taken from `SHA256SUMS.txt` on the published release.

The integrated source candidate used to establish repair provenance is:

`AIR_2.5.0_T12D_FOUNDATION_REPAIRED_INTEGRATED_CANDIDATE_BUNDLE.zip`

SHA-256:

`7244dd9dbe56b86d3180ff89684f7bdeca8712fad1c0ed9c64dac7cb489f6283`

That T12D archive is validation provenance for the repaired integrated candidate; it is **not** asserted to be byte-identical to the GitHub `AIR-core.zip` release asset, which is generated from the tagged repository source by `tools/build_release_bundle.py`.

## Known boundaries

- AIR remains a **prompt-compiled runtime**; no backend AIR enforcement is claimed.
- Universal cross-model/cross-host behavioral parity is not yet established.
- Specialist behavioral coverage remains broader than the targeted preview smoke.
- Preview users should treat named platform/model compatibility as empirical rather than guaranteed.
- Security-sensitive findings should not be posted publicly with exploitable details; use the repository's private security reporting path where available.

## Feedback

This preview intentionally uses real-world field feedback as part of AIR's development loop. Please report reproducible bugs through GitHub Issues and use GitHub Discussions for questions, design discussion, integration experiences, and feature ideas.

When reporting a behavioral issue, include the AIR Kit release, AIR Foundation version, model/provider, host/platform, exact prompt or reproduction sequence, expected behavior, observed behavior, and visible AIR output when possible.
